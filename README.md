# Медицинский портал
Внутренний портал для сотрудников ГБУЗ РБ ГДКБ №17 г. Уфа.

Проект не является SaaS. Это закрытая внутренняя система для одной больницы.

---

# 🎯 Назначение системы

Портал предназначен для:

- Публикации объявлений
- Размещения документов (дерево разделов, PDF и другие файлы)
- Подачи заявок (ИТ, АХЧ, метролог, транспорт) — прямо с промо-сайта без авторизации
- Публичной проверки статуса поданной заявки по её номеру
- Сообщения о нежелательных событиях (инцидентах) — без авторизации
- Управления справочниками (отделения, виды и типы нежелательных событий, автомобили)
- Аналитики по заявкам и инцидентам с экспортом в XLSX
- Уведомлений в мессенджер Max

# 🗄 База данных

Основные сущности:

- `users` — сотрудники, роли, поля привязки Max
- `roles` — RBAC и флаги доступа
- `departments` — отделения (`care_type`: Стационар / Поликлиника)
- `incident_view_types` — виды нежелательных событий
- `incident_types` — типы инцидентов (с привязкой к видам)
- `incidents` — нежелательные события
- `announcements` — объявления
- `document_folders` — дерево разделов документов (`parent_id` для вложенности)
- `documents` — файлы документов (`folder_id`, `original_filename`)
- `it_requests` — заявки в ИТ (с полем `remote_access_id` для TeamViewer/AnyDesk)
- `ahch_requests` — заявки в АХЧ
- `metrologist_requests` — заявки метрологу
- `transport_requests` — транспортные заявки
- `vehicles` — автомобили для назначения на транспортные заявки
- `organization` — логотип и hero-изображение портала

SQL-скрипты лежат в `backend/sql/`. Новые изменения схемы добавлять туда же отдельным пронумерованным файлом.

# 🌐 Промо-сайт (публичная часть)

Доступен всем без авторизации. Состоит из:

- **Hero-секция** — заголовок, описание, 5 кнопок для подачи заявок через модальные окна. Hero-изображение управляется из админки.
- **Новости** — объявления, опубликованные администратором
- **Документы** — баннер-ссылка на страницу `/documents`
- **Страница `/documents`** — дерево разделов с навигацией по папкам. У каждого файла кнопки «Открыть» (в новой вкладке) и «Скачать» (с оригинальным именем файла)
- **Шапка** — кнопка «Статус заявок» (выпадающее меню), вход в кабинет, навигация

Все 5 форм заявок (инцидент, ИТ, АХЧ, метролог, транспорт) открываются как модальные окна прямо с главной страницы. Авторизация не нужна.

# 🔍 Публичная проверка статуса заявки

Любой посетитель может ввести номер заявки и узнать её текущий статус.

Кнопка **«Статус заявок»** в шапке → выпадающее меню → выбор типа:
- Заявка в ИТ
- Заявка метрологу
- Заявка в АХЧ
- Транспортная заявка

Возвращает: статус, ФИО, отделение, описание, комментарий исполнителя.

# 📋 Форма "Нежелательное событие"

Форма публичная. Авторизация НЕ требуется.

После отправки данные сохраняются в БД со статусом `new`.
Контролю качества уходит уведомление в Max (если аккаунт привязан).

## Поля формы:

- Дата события
- Время события
- Место
- ФИО пациента
- Дата рождения пациента
- Обстоятельства
- ФИО сотрудника
- Должность сотрудника
- Присутствие законного представителя
- Отделение (select из БД)
- Вид нежелательного события (select из БД)
- Тип инцидента (select из БД, зависит от вида)
- Степень тяжести
- Последствия

- **Экспорт в XLSX** (выгружается текущая выборка)

# 📄 Документы

Администратор (и контроль качества при флаге `canManageDocuments`) создаёт дерево разделов любой вложенности и прикрепляет файлы к нужному разделу.

В таблице документа есть кнопки: открыть PDF и удалить. При редактировании документ можно перенести в другой раздел.

На диске файл хранится как технический идентификатор (`timestamp_random.ext`).
Оригинальное имя сохраняется в `documents.original_filename` и используется при скачивании.

# 📋 Заявки — общая модель

Все типы заявок (ИТ, АХЧ, метролог, транспорт) работают по одной модели:

- Подаётся с промо-сайта без авторизации
- Исполнитель в своём кабинете видит список заявок
- Может фильтровать по статусу и отделению
- Меняет **статус**: `new` → `in_progress` → `done` / `cancelled`
- Добавляет **комментарий** (виден при проверке статуса публично)
- При создании заявки уходит уведомление в Max исполнителям
- При **смене статуса** также уходит уведомление в Max с деталями заявки

### ИТ-заявки
Дополнительное поле — **ID удалённого доступа** (TeamViewer, AnyDesk и др.).

### Транспортные заявки
Диспетчер может **назначить автомобиль** на заявку, выбрав из справочника.
Диспетчер управляет справочником автомобилей прямо из своего кабинета (добавить / удалить).

# 📈 Аналитика

Доступна администратору и главному врачу.

- Линейный график по дням за выбранный период

- Фильтр по типу (один или все)
- **Экспорт итогов в XLSX**

# 💬 Уведомления Max

Односторонние уведомления через Bot API (`https://platform-api.max.ru`).
Токен бота: `MAX_BOT_TOKEN` в `backend/.env`.

Сотрудник привязывает Max в личном кабинете (раздел «Уведомления Max»):

1. Узнаёт свой числовой Max ID через бота `CHECK ID`
2. Вводит ID на портале — бот присылает одноразовый код (TTL 10 минут)
3. Вводит код в кабинете — аккаунт привязывается

После привязки можно выключить уведомления или отвязать Max.

Уведомление уходит всем пользователям нужной роли с `max_chat_id` и включёнными уведомлениями:

| Событие | Роль | Поля в сообщении |
|---------|------|-----------------|
| Новая заявка в ИТ | `it_department` | №, отделение, кабинет, телефон, описание |
| Новая заявка метрологу | `metrologist` | №, отделение, кабинет, телефон, описание |
| Новая заявка в АХЧ | `facility` | №, адрес, отделение, телефон, описание |
| Новая транспортная заявка | `dispatcher` | №, отделение, инициатор, дата/время, маршрут, цель, пассажиров |
| Нежелательное событие | `quality_department` | основные поля инцидента |
| Смена статуса заявки в ИТ | `it_department` | №, новый статус, отделение, кабинет, телефон, описание |
| Смена статуса заявки метрологу | `metrologist` | №, новый статус, отделение, кабинет, телефон, описание |
| Смена статуса заявки в АХЧ | `facility` | №, новый статус, адрес, отделение, телефон, описание |
| Смена статуса транспортной заявки | `dispatcher` | №, новый статус, отделение, маршрут, цель, пассажиров |

Статусы в уведомлениях отображаются на русском: **Новая**, **В работе**, **Выполнена**, **Отменена**.

Карточка привязки доступна в кабинетах: ИТ, метролога, АХЧ, диспетчера и контроля качества.

Бот не принимает входящие сообщения (webhook не реализован).

# 🔐 RBAC (Role-Based Access Control)

Доступ к разделам определяется ролью пользователя.

## Роли и их кабинеты:

| Роль | Кабинет / доступ |
|------|-----------------|
| Администратор | Полный доступ: заявки, инциденты, справочники, документы, пользователи, организация, аналитика |
| Главный врач | Все заявки + инциденты + аналитика (только чтение) |
| Контроль качества | Инциденты + типы/виды инцидентов + документы (при флаге) + Max |
| ИТ отдел | ИТ-заявки + Max |
| АХЧ отдел | АХЧ-заявки + Max |
| Метролог | Заявки метрологу + Max |
| Диспетчер | Транспортные заявки + управление автомобилями + Max |
| Сотрудник | Только промо-сайт |

## Принцип:

Backend проверяет права через middleware.
Frontend скрывает интерфейс на основе роли — это вспомогательная мера, основная защита на бэкенде.

# 🧾 Администрирование

Администратор может:

- Управлять отделениями (добавить, переименовать, удалить)
- Управлять видами и типами нежелательных событий
- Публиковать и редактировать объявления
- Создавать дерево разделов и загружать документы
- Просматривать все заявки и инциденты, менять статусы, добавлять комментарии
- Управлять пользователями (создание через регистрацию, редактирование, удаление)
- Вести справочник автомобилей
- Загружать логотип и hero-изображение организации
- Смотреть аналитику и экспортировать в XLSX

Форма инцидента НЕ редактируется администратором. Она фиксирована в коде.

# 🚀 Деплой

## Требования к nginx

Обязательно наличие `try_files` для SPA-роутинга (страница `/documents` и другие пути):

```nginx
location / {
    root /путь/до/dist;
    index index.html;
    try_files $uri $uri/ /index.html;
}
```

Для загрузки файлов увеличить лимит:

```nginx
client_max_body_size 50M;
```

## Миграции БД

SQL-скрипты применяются вручную по порядку номеров:

```bash
psql -U postgres -d medportal -f backend/sql/020_document_folders.sql
```

## Переменные окружения backend (`.env`)

```
PORT=4000
DB_USER=postgres
DB_HOST=localhost
DB_NAME=medportal
DB_PASSWORD=...
DB_PORT=5432
JWT_SECRET=...
JWT_EXPIRES_IN=1d
MAX_BOT_TOKEN=...
CORS_ORIGIN=https://your-domain.ru
```

## Переменные окружения frontend

```
VITE_API_URL=https://your-domain.ru/api
VITE_IS_SHOW_REGISTRATION=false
```
